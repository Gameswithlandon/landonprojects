Privacy Policy

Effective September 24, 2026

This policy describes how the hosted Synapse Discord bot handles information. Synapse is operated by Landon. It connects a public community server (a Spoke) to a private staff server (a Hub), or runs both roles in one Standalone server.

1. How Synapse Accesses Discord

Synapse operates strictly through slash commands, modals, and message components. It does not request or use Discord’s Message Content intent. It does not read, store, or scan the text of ordinary channel messages. The only content it receives is what you submit in a command, button, select menu, or modal, plus the Discord IDs Discord attaches to that interaction.

2. Information We Store

Operational data is stored in PostgreSQL. Discord snowflakes are stored as text, not as JavaScript numbers. Records can include:

  • Server IDs, whether a server is a Hub, Spoke, or Standalone, the Hub link code, the triage channel ID, subscription tier, log channel ID, and AI smartness setting.
  • Hub-to-Spoke links, and pending Spoke link requests (requesting server, Hub, requesting user ID, and request time).
  • Staff role mappings: role ID, Hub ID, permission level, and flags for quotas, leave approval, and strikes.
  • Staff profiles: user ID, Hub ID, duty status, weekly quotas, and an optional shift start time.
  • Subscription end dates when a referral or Top.gg vote grant applies.

We do not store message content, voice audio, or a full member list. Link codes are secrets for joining a Hub. Treat a leaked code as compromised and rotate it with the setup command.

3. How We Use Information

We use this data to route Spoke interactions to the correct Hub triage channel, to enforce Spoke limits and staff permission levels, to show staff lists, and to apply the subscription tier you are on. Future AI features, if enabled, would use command and ticket context you submit to the bot, not a scrape of channel history, and would be sent to Google’s Gemini API only for that request.

4. Data Retention

Configuration, links, staff roles, and staff profiles stay while the server uses Synapse, and are deleted or detached when setup is reset or a person is fired. Ticket and operational logs follow the retention window of the Hub’s tier:

TierLog retention
Starter7 days
Growth30 days
Network90 days
EnterpriseWhile the subscription is active (permanent for that term)
BespokeAs agreed for that instance

Pending link requests that are approved or denied are removed from the request table when the review finishes. Database backups, if taken for the host, follow the host’s backup cycle and are not a second public copy of your server.

5. Third Parties

  • Discord, because the bot must call Discord’s API to post triage messages, assign roles, and answer commands.
  • Stripe, if you pay for Growth, Network, Enterprise, or Bespoke. Payment is handled off Discord through a Stripe payment link. We do not store full card numbers.
  • Top.gg, if your staff vote for the bot. Vote counts are used only to apply the published vote reward.
  • Google Gemini, only if an AI feature is turned on for your Hub and you invoke it. The smartness tier is a setting on the Hub, not a copy of your chat.

We do not sell personal information. We do not use the data for advertising.

6. Storage and Security

The PostgreSQL database runs on infrastructure operated for the hosted bot. Access is limited to operating Synapse. Cross-server actions check the stored Hub-and-Spoke link before they run.

7. Your Choices and Rights

Server administrators can rotate a link code, change the log channel and smartness tier, remove a staff role mapping, fire a staff profile, or remove the bot. To ask for a lookup or deletion of the rows tied to your user ID or server ID, contact Discord user zerge5757 or open a request in the Synapse Support server. We may need to keep a record where Discord, payment disputes, or abuse investigations require it.

Synapse is not directed at children under 13. Discord’s age rules still apply. Do not submit another person’s private information in a command unless your staff workflow requires that ID and you have a right to process it.

8. Changes to This Policy

We may update this policy by posting a new version here and changing the effective date. The current version is the one on this page. Use of the bot is also covered by the Terms of Service.

9. Contact

Privacy questions and data requests may be directed to Discord user zerge5757 or raised in the Synapse Support server. These are the only official contact channels.
